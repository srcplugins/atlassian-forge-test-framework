# Changelog

## Unreleased

- **App readiness:** one readiness probe for app frames, with four stages in order: `attached`, `document`, `placeholder` and `root`. The page guard fails a test whose app frame isn't ready within `appLoadLimit`, now 30 s (it was 15 s, shorter than the lanes' own 30 s assertion timeout), with an error and an `app-readiness` annotation naming the stage, and still records the load time of a frame that is ready later. `appReady(page)` from `/jira` and `/confluence` waits for the app on a page and fails naming the stage; `projectPage`, `panel` and `spaceSettingsPage` call it (`{ ready: false }` skips it). In a `forge-test suite` step, each readiness failure is listed with its test and stage in the summary and the receipt (`steps[].readiness`), through `FORGE_TEST_STEP_RESULT` and `recordStepResult`.
- **Read retries:** a Jira or Confluence GET (the clients, `confluenceCall`, `doctor` and `preflight`) that fails on transport (a dropped or stalled connection: `ECONNRESET`, `ETIMEDOUT`, "socket hang up", "fetch failed", a request timeout) or with HTTP 502, 503 or 504 runs once more after 2 s and logs the retry with the failure's kind. Writes are never retried. `retryRead` from `/core` does the same for other reads, and transport errors carry `transient`.
- **One run per site:** `forge-test lane` takes the site lease and holds it while Playwright runs, so a suite started meanwhile waits for it and another lane refuses. Before, a lane only checked the lease, so two lanes, or a suite started during a lane, could share the site. A lane refuses at once while another run holds the site; a waiting or refusing run names the holder and how long it has held the site (the lease records when it was taken). `forge-test lease [--json]` and `siteLease(api).status()` show the holder read-only, and `FORGE_TEST_LEASE_HOLDER` names a local run.

- **Confluence foundation:** opt-in read-only client, product-access validation, separate private-state paths, space/page/settings navigation and a page guard based on the shared Forge watcher. Covered offline; Confluence fixture writes, CLI lanes and hosted selectors remain unverified. Jira keeps its existing watcher defaults.

- **Rovo agent selection:** `openRovoChat` counts the gallery's matching agents only after the gallery's server search for the agent's name has answered and the list holds steady. Jira first filters the agents it already loaded, which can hold one of two same-named agents (a development and a production installation), and lists the other only when its search answers, a second or more later. The count read 1, so the chat could open the wrong installation's agent without the inventory check. `isAgentSearch(request, agent)` recognizes that search. Once the count is known, a reopened gallery that settles on fewer (or more) agents is opened again, up to three times, instead of failing: after its search had answered, Rovo's gallery still listed one of the two agents for the whole wait. `fullGallery(open, expected)` does the reopening.
- **Site lease priority:** a `forge-test suite` run with `FORGE_TEST_LEASE_PRIORITY=1` (a release) goes ahead of other waiters, and a suite holding the site pauses before its next step for it, then runs its passed prerequisites again and continues. `runSuite` takes a `pause` hook for this, and `siteLease` a `priority` option, `priorityWaiting()` and `acquire({ wait })`. A release otherwise waited for another repository's whole suite.
- **Saved sessions:** `lane`, `suite` and `restore` refuse to run with an expired saved session and name the profile to sign in again with `forge-test login`; one expiring within a week warns (a GitHub annotation on a runner) and names `forge-test renew`. `secrets` refuses to copy an expired session.
- **Session renewal:** `forge-test renew [profile...]` extends saved sessions without a sign-in, so a machine that keeps them can renew on a schedule and copy them with `secrets`. Atlassian extends a session's sign-in cookies when it opens the site and the Atlassian account page; `renew` saves a session again only when Jira still returns its account and the sign-in lasts longer than before (`renewalOutcome`). `secrets --sessions-only` then copies just the renewed sessions, leaving the configuration, credentials and identity pins as they are.
- **Lanes and the site lease:** `forge-test lane` refuses to start while another run holds the site lease and names that run, so a local lane can't share fixture spaces with a running suite. A suite's own lanes run under its lease.
- **Cleanup:** a fixture whose recorded custom field value differs is cleaned up when Jira's history shows no change since the create, as when a journey recorded a save and failed before making it. Before, cleanup refused it and the run's journal stayed unresolved.
- **Suite receipts:** every `forge-test suite` run writes a JSON receipt (suite, directory, result, and each step's outcome and times) to `sites/<host>/e2e/suites/` in the private state, for measuring first-pass rates and repair time.
- **Page guard:** every test from `/jira` fails when Jira shows an error flag the test didn't declare ("Created Story with exceptions", "Something went wrong", "We couldn't load …") or when an app frame stays behind Jira's loading placeholder for longer than `appLoadLimit` (15 s). Declare expected flags with `test.use({ expectedFlags })` or `pageGuard.allowFlag(pattern)`.
- **Create-form fixtures:** `owned.browserIssue` returns once Jira shows the Create outcome flag, and fails at once if it's an error, so a field that Jira couldn't save after the create fails the test.

## 0.3.1

- **Create-form fixtures:** `owned.browserIssue(summary, typeId, { fill, submit })` journals a work item that the journey creates through Jira's own Create form. The run marker ends its summary and the work item is found by it. A failure while filling the form wrote nothing; a failed submit is reconciled by reading, never repeated.

## 0.3.0

First public release.

- **Configuration:** one JSON object, from an environment variable, a file or `.local/forge-test.json`, names your owned sites, Forge installations, fixture spaces and marker namespace. Every command refuses a site it doesn't list.
- **Commands:** `forge-test doctor`, `preflight`, `login`, `prepare`, `install`, `lane`, `suite` and `cleanup`, plus `secrets`, `restore` and `mask` for CI.
- **Journaled fixtures:** the `owned` fixture creates marked work items in a fixture space and records intent before every write. A failed create is reconciled by reading, never repeated. Cleanup rechecks markers and fields and deletes only what the run created, and `forge-test cleanup` recovers a run after a hard stop.
- **Fixture profiles:** `standard` (the app's fixture space), `identity` (pinned accounts in an isolated permission scheme), and your own through `registerProfile`, including team-managed spaces.
- **Suites:** ordered steps from `forge-test.mjs` with prerequisites and per-step cleanup, so one run reports every independent failure. A site lease makes suites that share a site take turns.
- **Playwright lanes:** `features` in Chrome and `compatibility` in Chrome, Firefox or WebKit; serial, no retries.
- **Jira helpers:** a REST client whose transport failures name the stage and the kind of failure but never a message, header or body, space page and work item panel locators, resolver observation, theme changes that are restored afterwards, a contrast check, Rovo agent selection and Jira's first-run dialog.
- **CI:** state copied into GitHub environment secrets, private values masked in logs, and evidence and carried run journals encrypted with age.
